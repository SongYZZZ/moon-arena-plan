# MoonArenaPlan：面向端侧流水线的静态内存规划与核验

项目类型：原创 MoonBit 库与命令行工具。仓库：https://github.com/SongYZZZ/moon-arena-plan 。许可证：MIT。

**目标与价值。** 端侧数据采集和模型处理中，内存需求由缓冲区的同时存活关系、对齐、设备可访问区域与持久状态共同决定。项目为已知串行执行顺序的流水线生成多内存区静态布局，并从原始清单独立核验，帮助开发者在集成前发现布局与预算问题。

**现有基础与实质贡献。** TFLM 等框架已有 arena 复用与离线分配机制。本项目独立实现允许内存区集合、固定采集缓冲区、图生命周期推导及外部布局核验，形成可被 MoonBit 程序和 CI 调用的工具；核心不依赖推理框架运行时。当前库、CLI 与测试已实现。

**核心功能与验收终点。** 完整支持自定义 JSON schema 1 中的容量、字节数、两端包含的生命周期、对齐、允许内存区及固定偏移；输出确定性布局、逐区峰值、冲突证据和 C 偏移头文件。严格拒绝未知字段与小数时间步。验收通过可运行案例、核心正反例、独立黑盒核验、C 数组回放及检查／构建／测试 CI 完成。

**场景一：串行处理内存复用。** 开发者输入三个存活区间互不重叠的 64 字节缓冲区，得到高水位 64 字节的布局，对照独立预留的 192 字节，核验复用效果。

**场景二：采集与特征区协同配置。** 集成人员输入固定在 dma 区的 128 字节采集区，以及同一时段存活、可选 dma／fast 的 128 字节特征区，得到跨两个 bank 的布局与访问约束检查结果，用于配置评审。

**场景三：变更后的预算回归。** 输入在交接步同时存活的两个 64 字节对象和 96 字节预算，工具输出超预算失败；CI 据此阻止把不满足声明预算的布局交付下游。

**实现边界。** 场景是可复现的工程样本，尚无真实设备或用户采用记录。算法采用确定性贪心，不保证最优；清单需完整提供 scratch、持久对象与访问限制。当前不承诺 ONNX／TFLite 导入、动态形状、并行时序、算子执行、整机 RAM 估算或硬件部署成功。
